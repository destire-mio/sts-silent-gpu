# E4 模仿训练退步与长线构筑改进调查

日期：2026年11月8日，北京时间。对象：STS1 Silent A20 E4 策略训练。

**优先验证搜索标签能否重复成立，以及学习纠错时是否损伤原能力；长线构筑优先补充真实后续回报的价值校准，再试跨战斗的构筑回报。** 现有证据支持具体机制的排查顺序，尚不足以把两次退步归结为一个原因。

通俗地说，搜索能现场试出更好的动作，但训练把这些有不确定性的建议压成了确定答案。第一版还大量强化了原来的选择；第二版限制了更新总量，却没有验证每个答案，也没有约束其他局面的行为变化。

“长线构筑缺少真正的结果反馈”需要更准确地表述：**已有结果奖励和跨片段价值传递，但构筑主要依赖短片段后的价值估计，缺少对真实长期后果的独立校准。** 不是完全没有反馈，也不是奖励只能传64步。

本报告包含历史日志与源码核对、CPU合成机制检查，以及尚未执行的游戏实验方案。发布基准为 `codex/e4` 的 `644d8d0f21372c9a59d6a14ca6f8c4dcfeb2e199`；报告不改变运行中的训练或调度。

## 第一次模仿训练的主要问题

专家v1从更新1357开始，位于64h至66h之间；70h不是开始前的基线。

| 末轮指标 | 64h纯PPO | 66h专家v1 | 68h专家v1 |
| --- | ---: | ---: | ---: |
| 裁剪前总梯度范数均值 | 0.4895 | 30.1312 | 33.4098 |
| 梯度裁剪比例 | 39.1% | 100% | 100% |
| 战斗归一化熵 | 0.3334 | 0.1397 | 0.1198 |
| 选牌归一化熵 | 0.1530 | 0.0828 | 0.0664 |
| 普通平均楼层 | 30.0254 | 30.1650 | 29.7373 |

这三个检查点均为8卡、观测v13。开启模仿后更新尺度和动作分布先发生明显变化，分数没有立即下降；后续70h的29.3496层降到72h的26.7471层，配对差−2.6025、标准误0.3571。后段另有观测版本和卡数变化，不能单独归因模仿。[64h][eval64]、[66h][eval66]、[68h][eval68]、[72h][eval72]

v1的两个设计事实与上述变化一致：

1. **标签独立归一化并乘固定权重0.5。** 几十至几百条专家标签仍获得固定整体损失权重，不随PPO的几十万至百万条样本而缩小。66h一轮107个专家标签对1,048,575个有效PPO动作，按目标函数系数计算，单个专家样本约为单个PPO样本的4,900倍权重；这不代表实际梯度也大4,900倍。
2. **多数标签没有纠错。** 被检查的轮次中约74%至83%的搜索动作与原argmax相同，仍作为唯一正确动作做硬交叉熵训练。它进一步锐化已有偏好，没有保留原策略的不确定性。战斗模仿与PPO共用编码器、Adam及总梯度裁剪，影响可以传播到选牌与价值表示。[v1设计][expert-design]

启动后KL曾达约0.05489，学习率从约6.667e−5降至1.317e−5。这支持“更新尺度和置信度受扰”的解释。历史仅记录总梯度，且熵包含强制动作，不能由此精确算出CE的梯度占比，或直接宣布探索完全塌缩。

## 第二次模仿训练解决了什么与留下什么

v2只学习搜索改选，并将跨卡平均后的CE梯度范数限制为PPO总梯度的0.25。实现确实做了同步、除以卡数、限幅、合并，再执行原来的AMP、总裁剪和Adam。78h至80h均层仍从29.8867降至28.0420，配对差−1.8447、标准误0.3809。[v2评测][eval80]、[梯度合并][expert-code]

### 搜索胜者的可靠性没有独立验证

搜索只在符合条件的局面比较原策略前4个动作，每个动作8次推演；后续动作使用原网络argmax，最多256步，结束时加同一个价值网络的估计。它用同一批8次结果先选均值最高者，再要求相对原动作的配对均值差大于1个标准误。此门槛没有独立复验，也没有处理挑最大值带来的选择偏差。[搜索实现][lookahead]

整体搜索平均更强，不等于每个改选都可靠。少数错误改选可以与整体正收益同时存在，而硬模仿会一起强化它们。

CPU零信号检查：4个候选真实价值相同、每候选8个独立标准高斯分数，沿用上述选择规则，固定随机种子170，共30,000次决策。10,402次通过门槛，占34.6733%；入选时平均优势0.75336，独立复验的平均优势为0.000424，仅17.7466%的入选动作在复验中再次超过1个标准误。**这是筛选机制的反例，不是实际游戏标签错误率。** 可复现代码见附录。

### 信息压缩和样本覆盖不足

搜索报告原本有候选均分、配对差和标准误，但专家训练只保存局面、动作、掩码等信息，用等权硬交叉熵学习。微弱改选和稳定救命动作没有区别；原策略完整概率分布也没有用于能力保持。

80h末五轮只有116、55、105、77、19个标签，平均每个全局优化步约9.67、4.58、8.75、6.42、0.95个。每个标签每epoch使用一次，共两个epoch，并不是每一步重放全部标签。专家采集常在1至3个tick就碰到时间预算，来自持续的独立专家车道，不能等同覆盖全部学生轨迹。[样本与梯度记录][eval80]

v2的战斗熵反而高于早先纯PPO均值，因此不能把两次都解释为同一种“策略变得过度确定”。更应检验标签噪声、学生实际状态覆盖，以及共享网络的能力干扰。

### 总梯度上限不等于行为保持

25%的参照包含actor、value和entropy以及全部参数。它不限制每个参数方向、每类决策的概率变化，也不直接限制Adam后的更新。

用实际合并函数的CPU检查：原梯度为 `[1, 0.001]`，专家方向集中在第二维。限幅后专家梯度约为 `[0, -0.250000125]`，总范数恰为原梯度的25%，但第二维合并后变为−0.249000125。该方向被反转，说明总量约束不是局部行为的保证；这仍不是历史能力损伤的直接测量。

### 已排除或不能据以定因的解释

- 暂未发现动作、观察打包、掩码错位的证据，已有原生打包对齐检查；该检查不验证改选的真实收益。
- 专家样本只进入CE，不进入PPO优势和概率比，不能仅因专家返回旧概率就认定PPO接错。
- v2的DDP调用顺序问题在78h前已修复，不能拿它解释修复后78h至80h的全部退步。
- 两次回滚只恢复模型权重，保留后续Adam等状态；回升不是“关闭CE即可治好”的干净因果证据。[82h回滚记录][eval82]

## 长线构筑的问题应如何定义

当前观察含完整主牌组、升级、遗物、药水及非战斗地图。Stage12所有有效动作都参与PPO，未冻结构筑。活局正确在64步尾部bootstrap，真实终局清零接续，使用γ=1、λ=0.995。[观察编码][observation]、[训练实现][learner]

对未终止的64步片段，第一步λ-return中尾部价值估计的系数为0.995^63≈0.7292，64个位置的平均尾部系数约0.8576。这表明后续收益大量依靠价值估计接力，不能将它解释为“价值一定错”或“73%的真实收益被忽略”。

已有类型级价值解释方差使用同网络bootstrap形成的目标，并且仅记录一次。它衡量对当前训练目标的拟合，不是独立长期回报的准确性。第一幕Boss、第二幕入口的价值与最终楼层相关，也不能替代“同一局面选A还是B”的差值准确性。[诊断实现][diagnostics]、[调用位置][runner]

当前训练动作中战斗约75%，选牌约2.5%、商店约1.5%，所有类型共同标准化优势并按动作平均损失。比例低不自动证明梯度小，须测各类型的实际贡献。中途开局有55%跳过部分上游构筑，可增加后段经验，但不会直接补出被跳过的选牌行为梯度。

选牌推演最多3场战斗、到当前幕Boss或1024步即停，后续仍靠原战斗策略和原价值函数。若一张牌的收益要到下一幕，或要求策略尚不会执行的配合，评价会受限。96h正确随机化后的选牌收益仅+0.6953层、标准误0.5121；88h较大收益因未随机化、看见真实未来而作废。[96h三模式对照][eval96]

## 长线构筑的可实施方法与取舍

### 先建立独立的长期结果校准

第一优先级是固定策略，从训练种子保存真正需要选择的选牌、商店、升级、路线状态，并按幕和血量分层。使用独立的整局随机化，从状态继续至真正终局，得到与现有RewardLedger及归一化一致的剩余回报：

`G_t = sum(normalized_r_k, k=t..terminal-1) = (rawLedger_terminal - rawLedger_t) / 156`

按游戏种子划分训练、验证和最终验收；同一局面的分支和同种子的相邻局面归于同一组。对完整后续结果检查价值校准、误差、同类局面排序。另记第二幕Boss是否通过、损血及药水消耗，用于解释，但不擅自把这些指标相加成为新奖励。

到Boss的阶段性收益不等于当前价值函数预测的完整剩余收益，不能混用。若时间帽内没有跑到终局，应存为截尾并报告完成率，不能把未完成当死亡、零回报，或只分析容易完成的样本后宣称无偏。

完整回报有随机性，须报告重复分支的误差范围。回报对应特定策略版本与执行方式；用argmax跑出的结果不能直接冒充训练采样策略的价值。第一阶段作为冻结策略诊断；若后来进入价值训练，保持策略版本、动作选择方式明确。旧离线轨迹不直接混入当前PPO actor更新。

### 优先试价值辅助监督

若现有价值明显错估真实后果，先用完整回报训练一个小的辅助价值头；首轮可冻结编码器，检查已有表示能否支持长期预测。随后才比较允许少量共享表示更新，并监控原有策略变化。若独立验证误差改善而游戏成绩不变，说明预测改善尚未转化为更好的动作选择，不能因此宣布解决平台。

辅助的“本幕Boss通过概率”头可以提供更易解释的检查量，但它是额外目标，不是原完整回报的等价替换。生存概率不能单独指导所有选牌，否则可能偏向保守活过本幕而牺牲后幕能力；未到达终点的截尾样本也不能简单标0。

### 用成对分支区分选牌判断与战斗执行

对同一选牌状态与候选，使用相同的世界随机化成对继续，减少无关随机差异。先用发现样本筛选，再以独立验证样本确认优势；相同种子不保证不同动作路径消费相同随机数，因此仍需检查随机化实现并报告实测方差。

小规模比较两种固定后续执行器：普通战斗策略与较强的战斗推演。若候选排序随执行器明显变化，说明构筑评价受到“能不能发挥这张牌”的限制；若短推演排序与真实较长后果不同，优先检查推演长度和末端价值。结果分别记为各执行器条件下的动作价值，不把强搜索执行器的回报直接当成普通学生已经可实现的收益。

这一步比预设“应该多拿某种牌”更有信息量，也能连接战斗模仿与构筑改进：先教会能发挥配合的战斗动作，再重新评估相应构筑。

### 再试跨战斗的宏决策回报

若确认长程信用分配是瓶颈，可对真正需要选择的非战斗节点，累计至下一次关键非战斗节点或幕Boss的奖励。当前γ=1时，持续时间不会引入额外折扣，宏步残差为：

`delta_macro = accumulated_reward + V_macro(next_state) - V_macro(state)`

真正终局的尾值为0；若将来γ<1，尾值需乘γ^持续动作数。λ按宏决策推进，而非被中间每次出牌反复衰减。这样一次选牌的反馈能跨过战斗，仍不需要给“拿牌”凭空加正奖励。

先冻结战斗执行器，以隔离构筑学习；宏决策状态和值函数须单独定义。首轮优先将宏回报用于构筑价值辅助目标。进一步接回PPO actor时，保留真实行为概率、终止/截尾和策略版本，只有符合on-policy条件的数据进入actor；仅保存旧动作概率不足以保证旧轨迹可以使用。战斗继续原目标，避免把同一奖励无说明地重复作为两个actor优势。此方案改变估计器，需要单变量对照，不能仅凭公式宣布更优。

### 类型平衡和回报重分配放在后面

定期记录去除强制动作后的各类型优势尺度、actor/value/模仿梯度范数与方向、策略KL和独立长期预测误差。若证实构筑信号被稀释，再适度调整该类采样或损失权重；重采样必须明确相应的权重和目标，不能机械按2.5%的频率放大40倍。

RUDDER式回报分解可作为后续研究：利用序列模型把延迟结果分配给关键历史决策。它额外引入回报预测、归因与保持回报等价的实现成本，当前不应优先于独立回报校准与宏决策对照；也不能把相关性归因直接解释为“这张牌造成胜利”。[RUDDER原论文][rudder]

## 建议执行顺序与停止条件

以下数量是用于限定首轮工作量的提案，不是已经完成的实验或既定GPU预算。按最小分支数预先算环境步和GPU秒上限，达到上限即保留未完成标记，不因结果不理想不断加样本。

| 阶段 | 最小工作 | 继续或调整的依据 |
| --- | --- | --- |
| A 标签复验 | 从学生实际访问的训练局面分层抽128个第二幕战斗状态；沿用8次发现，选出改选后另用独立随机化作配对验证；记录每候选分数、优势、标准误、原概率、状态及版本 | 总体平均优势覆盖发现阶段选出的全部改选；验证筛选后的子集另报，不能用同批筛选结果夸大收益。若总体收益消失，先改老师，不进入大规模模仿 |
| B 学会与遗忘 | 仅用复验可靠的训练标签，从同一完整检查点做少量更新；比较纯PPO、原硬模仿、带普通局面策略保持约束的模仿；另用留出局面测效果 | 标签拟合、留出纠错效果、普通战斗及构筑的KL/动作翻转、价值误差、实际Adam位移；拟合成功但普通能力下降时处理共享干扰 |
| C 构筑诊断 | 以128个非战斗局面起步，每类32个，按游戏分组留出；少量独立完整继续，并在子集做普通/搜索执行器成对候选比较 | 区分长期价值误差、候选排序误差和执行能力限制；未完成结果单列，精度不足则保持未决 |
| D 价值辅助目标 | 先固定编码器与执行策略，试完整回报辅助头；再按需要开放共享表示 | 验证集长期预测改善且原能力不退，再检查从头整局收益 |
| E 宏决策或类型平衡 | 仅在相应诊断成立后，分别测试，不在同一轮同时改奖励、模型、数据配比和优化器 | 同预算下的独立整局成绩及二幕条件通过率；有局部改善但整局退化则不扩大 |

dev112可作冻结能力参考，但仅有模型权重的文件不等于可恢复训练检查点。训练对照须从同一个完整模型、Adam、scaler、采样状态与RNG分叉；若旧优化器不可得，两边采用相同且明确的初始化方式。固定卡数或明确报告实际资源，比较GPU秒和有效交互量，不能仅按更新轮数比较。

当前固定1024开发种子用于跟踪，最终验收使用未参与标签筛选、调参和挑检查点的新种子。统计按游戏/种子聚类，不能把同一局的多个状态当独立游戏。均层、二幕条件通过率、从头到二幕的覆盖率、一幕能力及成本一起报告；预先固定主要比较和实际有意义的最小改善，不能只凭一次最佳分数或CE下降决定继续。

## 附录 CPU筛选反例复现

下面仅检验“先在同一批样本挑赢家，再以1SE准入”的机制，不加载模型或游戏。Python标准库，固定seed170。分支分数在合成设定下相互独立，真实游戏的相关性和分数分布不同，不能将误选比例移作游戏结论。

```python
import math
import random
import statistics as st

rng = random.Random(170)
accepted = repeated = 0
discovery_sum = validation_sum = 0.0
for _ in range(30000):
    samples = [[rng.gauss(0, 1) for _ in range(8)] for _ in range(4)]
    means = list(map(st.mean, samples))
    best = max(range(4), key=means.__getitem__)
    if best == 0:
        continue
    d = [a-b for a, b in zip(samples[best], samples[0])]
    if st.mean(d) <= st.stdev(d) / math.sqrt(8):
        continue
    accepted += 1
    discovery_sum += st.mean(d)
    v = [rng.gauss(0, 1)-rng.gauss(0, 1) for _ in range(8)]
    validation_sum += st.mean(v)
    repeated += st.mean(v) > st.stdev(v) / math.sqrt(8)
print(accepted, accepted / 30000,
      discovery_sum / accepted, validation_sum / accepted,
      repeated / accepted)
# 10402, 0.3467333333, 0.7533608006, 0.0004242377, 0.1774658719
```
